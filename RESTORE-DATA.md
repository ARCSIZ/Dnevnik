ВОССТАНОВЛЕНИЕ ПОЛЬЗОВАТЕЛЬСКИХ ДАННЫХ НА BOTHOST

1. Остановите приложение.
2. Скачайте текущие файлы базы с сервера на компьютер как страховочную копию. Проверьте оба пути,
   если они существуют: /app/data/data.json и /app/data.json. Не удаляйте ни один файл.
3. Найдите именно СВОЮ старую резервную копию data.json. Не используйте data.json из ZIP с кодом,
   если не уверены, что это последняя база пользователей.
4. В настройках показана DATA_DIR=/app/data. Если DATA_FILE не задана, активный файл должен быть
   /app/data/data.json. Если задана DATA_FILE, используйте путь, указанный в её значении.
5. Загрузите старый data.json в точное место активной базы, сохранив перед этим копию текущего файла.
6. Замените на сервере только server.js файлом из этого архива. Не перезаписывайте остальные файлы
   проекта и не заменяйте data.json архивным файлом.
7. Запустите/пересоберите приложение. В логах должна появиться строка вида:
   База данных: /app/data/data.json; версия 3; пользователей N; групп M
   Проверьте, что число пользователей и групп похоже на ожидаемое, а затем проверьте вход.

Что исправлено в server.js:
- учитывает DATA_FILE; если её нет, учитывает DATA_DIR/data.json; иначе использует data.json рядом с сервером;
- старый root data.json автоматически копируется в постоянный каталог, если целевой файл там отсутствует;
- база с версией ниже 3 больше не сбрасывается в DEFAULTS — недостающие поля добавляются с сохранением данных;
- при повреждённом JSON сервер прекращает запуск, не перезаписывая файл пустой базой.

Если файл старой базы уже был перезаписан после неудачного запуска, ищите резервную копию в разделе
«Бэкапы» BotHost или на компьютере. Новый код не может восстановить содержимое, которого больше нет
ни в одном сохранённом файле.
